rxx embeds a Rhai scripting engine that lets you extend the editor with plugins. Plugins are scripts that can draw overlays, register custom commands, extend GPU pipelines, and react to user input.

overview

When launching rxx with the -p <plugin-directory> flag, rxx will scan the directory for .rhai scripts and load them.

After a script is loaded, rxx calls the Rhai init() function if it is defined in the script. This function is the entry point for plugin initialization: you can register commands, and set up global variables will define the plugin's state.

Variables declared inside init() are visible to other callbacks (draw, cmd_*, etc.), but variables defined in the outer scope of the script are not. This is due to working around Rhai's variable shadowing: each callback runs in a scope that would shadow script-level variables, so plugin state must be defined in init() to be shared.

There are many more rhai "hooks" that scripts can provide. Let's take a look at a very simple example of a plugin that implements a useful feature first: a classic vim 'current mode' indicator. 

// mode-vis.rxx - current mode indicator plugin

fn init() {
    // plugin constants
    const TEXT_POS = vec2(10.0, 46.0);
    const NORMAL_COLOR = rgb8(255, 255, 255);
    const VISUAL_COLOR = rgb8(0xff, 0x33, 0x66);
    const SCRIPT_COLOR = rgb8(0xff, 0x33, 0x66);
    // prints to stdout
    print(`mode-vis.rxx initialized`);
}

fn draw() {
    let mode_string = session.mode.to_string();
    let widget_string = `-- ${mode_string.to_upper()} --`;

    // draw current mode indicator
    if mode_string == "normal" {
        draw_text(TEXT_POS, widget_string, NORMAL_COLOR);
    } else if mode_string.starts_with("visual") {
        draw_text(TEXT_POS, widget_string, VISUAL_COLOR);
    } else if mode_string == "command" {
        // nothing - command mode is skipped
    } else {
        // script mode
        draw_text(TEXT_POS, widget_string, SCRIPT_COLOR);
    }
}

The draw() hook is called every frame by rxx when it composites the view. Your script receives no arguments; it reads from the global session (and other engine-provided globals) and uses drawing APIs like draw_text to paint overlays on top of the screen buffer. Here, the plugin reads session.mode, formats a label, and draws it at a fixed position with a color that depends on the mode. Anything you draw in draw() is part of the same frame as the rest of the UI, so overlays stay in sync with the rest of the editor's state.

registering new commands

From init() you can register custom commands that the user can invoke (e.g. via the command palette). Call register_command(name, description) with a command name and a short description. For each registered command, rxx will call a Rhai function when the user runs it.

The handler function must be named cmd_ followed by the command name with slashes replaced by underscores. For example, greet is handled by cmd_greet. The handler receives one argument (an args array of strings) and can read from session and your plugin's state. Here is a minimal example: 

fn init() {
    register_command("greet",
        "Say hello (optionally to a name)");
}

fn cmd_greet(args) {
    if args.len() > 0 {
        print(`Hello, ${args[0]}!`);
    } else {
        print("Hello!");
    }
}

Running :greet prints "Hello!"; :greet Alice prints "Hello, Alice!". State defined in init() is visible to your cmd_* handlers and other hooks (draw, view_removed, etc.), so you can keep plugin data in script-level variables and update it from commands.

other events

Plugins can react to view lifecycle and editor mode changes, and to mouse input. All of this uses optional hooks: define a function with the right name and signature and rxx will call it when the corresponding event occurs.

view lifecycle

When the user opens or closes a view, rxx calls view_added(view_id) and view_removed(view_id) if your script defines them. Use these to keep plugin state in sync with the set of open views. For example, if you track something per-view (e.g. a lookup table keyed by view id), remove the entry in view_removed so you don't hold stale references: 

fn init() {
    let lookup_views = #{};
    register_command("lt/on", "Add active view to lookup set");
    register_command("lt/off", "Remove active view from lookup set");
}

fn view_removed(view_id) {
    lookup_views.remove(`${view_id}`);
}

fn cmd_lt_on(args) {
    let vid = session.active_view_id;
    lookup_views[`${vid}`] = true;
}

mode changes and custom script modes

The editor has a current session.mode (normal, visual, command, or a script-defined mode). To implement a tool that takes over the canvas (e.g. rotate selection by dragging), build a new script Mode instance in init() with script_mode("description") and store the returned value. Then switch into it from a command with session.switch_mode(your_mode). While in that mode, only your plugin's mouse_input and cursor_moved hooks receive input; other plugins and the default editor bindings do not.

When the user leaves your mode (e.g. by pressing Escape), rxx calls switch_mode() on your script with no arguments. Use that hook to clean up: set plugin state back to idle, and call queue_effect(effect_view_damaged(view_id)) if you need the view to redraw. You can detect which mode was left via session.prev_mode. 

fn init() {
    let rotation_mode = script_mode("visual (rotation)");
    let in_progress = false;
    register_command("selection/rotate", "Rotates the selection");
}

fn switch_mode() {
    if in_progress && session.prev_mode == rotation_mode {
        in_progress = false;
        queue_effect(effect_view_damaged(session.active_view_id));
    }
}

fn cmd_selection_rotate(args) {
    if session.selection != () {
        in_progress = true;
        session.switch_mode(rotation_mode);
    }
}

mouse input

Define mouse_input(state, button, cursor) to receive button press and release events. state is one of INPUT_STATE_PRESSED, INPUT_STATE_RELEASED, or INPUT_STATE_REPEATED; button is MOUSE_BUTTON_LEFT, MOUSE_BUTTON_RIGHT, or MOUSE_BUTTON_MIDDLE. The cursor argument is a position in session/screen coordinates (e.g. cursor.x, cursor.y).

To map the cursor to pixel coordinates in the active view (e.g. for drawing or selection), use session.active_view_sub_coords(cursor, precision). The second argument is a sub-pixel precision in bits (e.g. 2 for quarter-pixel). The result is in view space, so you can compare it with session.selection or use it in your own logic.

Define cursor_moved(p) to receive continuous cursor updates while the pointer moves. p is in session coordinates. Use this for drag operations: combine with state you set in mouse_input (e.g. drag_start on press, clear on release) to compute deltas or angles and update your plugin state, then draw feedback in draw(). 

fn mouse_input(state, button, cursor) {
    if session.mode != rotation_mode { return; }
    let view = session.view(session.active_view_id);
    let d = view.zoom;
    let cursor_adj = vec2(cursor.x + d/4, cursor.y + d/4);
    let p = session.active_view_sub_coords(cursor_adj, 2);

    if state == INPUT_STATE_PRESSED && button == MOUSE_BUTTON_RIGHT {
        pivot = if p == pivot { () } else { p };
    }
    if state == INPUT_STATE_PRESSED && button == MOUSE_BUTTON_LEFT {
        drag_start = p;
    }
    if state == INPUT_STATE_RELEASED && button == MOUSE_BUTTON_LEFT {
        drag_start = (); last_p = ();
    }
}

fn cursor_moved(p) {
    if drag_start != () {
        // p in session coords; convert drag_start/pivot to session and compute angle
        let angle = vector_angle(pivot_session, drag_start_session, p.to_vec2());
        rotation_angle = angle;
    }
}

GPU pipeline hooks

For custom GPU work, scripts can define shade(encoder) and render(pass). Both are optional. They run during the frame's command encoding: shade first (with a command encoder), then the engine starts the main render pass and calls render with that pass.

shade(encoder)

shade(encoder) receives a command encoder. Use it to record your own compute or render passes. Call encoder.begin_compute_pass("name") to start a compute pass, or encoder.begin_render_pass("name", [color_attachment(texture, load_load(), store_store())]) to start a render pass that targets a texture (e.g. renderer.view_staging_texture(view_id)). Then set pipeline, bind groups, and vertex buffer on the pass and call pass.draw(...). The renderer API provides create_shader_module, create_render_pipeline_with_texture, create_vertex_buffer_from_sprite_vertices, create_view_transform_bind_group, create_ortho_custom_transform_bind_group, create_texture_sampler_bind_group, and related helpers. Use shade when you need to render into an offscreen or staging texture, or run compute, before the main view is composited.

render(pass)

render(pass) receives the active render pass for the current frame. The engine has already begun the pass; your script issues draw calls into it. Use session.active_view_id and session.view(vid) to get view position and zoom, and renderer.view_render_texture(vid) to bind the view's framebuffer. Set your pipeline, bind groups, and vertex buffer on pass, then pass.draw(vertex_count, instance_count, first_vertex, first_instance). Use render when you want to draw directly into the view (e.g. full-screen effects or overlays that must be part of the same pass). 

fn shade(encoder) {
    if in_progress {
        let staging_texture = renderer.view_staging_texture(session.active_view_id);
        let pass = encoder.begin_render_pass("cleanedge", [color_attachment(staging_texture, load_load(), store_store())]);
        pass.set_pipeline(pipeline);
        pass.set_bind_group(0, transform_bind_group);
        pass.set_bind_group(1, clipboard_bind_group);
        pass.set_vertex_buffer(0, vertex_buffer);
        pass.draw(6, 1, 0, 0);
    }
}

fn render(pass) {
    let vid = session.active_view_id;
    let view = session.view(vid);
    if view != () {
        let x = session.offset_x + view.offset.x;
        let y = session.offset_y + view.offset.y;
        let zoom = view.zoom.to_float();
        let view_bind_group = renderer.create_view_transform_bind_group(x, y, zoom);
        let view_tex_bind_group = renderer.create_texture_sampler_bind_group(renderer.view_render_texture(vid));
        pass.set_pipeline(script_pipeline);
        pass.set_bind_group(0, view_bind_group);
        pass.set_bind_group(1, view_tex_bind_group);
        pass.set_vertex_buffer(0, vertex_buffer);
        pass.draw(6, 1, 0, 0);
    }
}
