rxx scripting guide

home overview start lifecycle api

rxx embeds a Rhai scripting engine that lets you extend the editor with plugins. Scripts can draw overlays, register custom commands, create GPU pipelines, and react to user input — all without restarting the editor.

overview

There are two types of scripts:

  • .rxx plugins — placed in the plugins/ directory. These are full-featured plugins with lifecycle hooks, drawing, GPU access, and custom commands.
  • init.rhai — placed in config/init.rhai. Same capabilities as .rxx plugins. Runs on startup alongside the built-in plugins.

Both formats use the Rhai language. If you know Rust or JavaScript, Rhai will feel familiar — it has let bindings, fn functions, string interpolation with `${expr}`, maps (#{}), and dynamic typing.

getting started

your first plugin

Create a file in the plugins directory, e.g. plugins/hello.rxx: 

fn init(session_in, renderer_in) {
    let session = session_in;
    let renderer = renderer_in;
    print(`hello.rxx loaded!`);
}

fn draw() {
    draw_text(
        vec2(10.0, 30.0),
        "hello from rxx",
        rgb8(0, 255, 0)
    );
}

Save the file and rxx will hot-reload it. You should see green text in the top-left corner of the editor.

Scripts are loaded alphabetically from the plugins/ directory. Variables declared at the top of init() persist across all subsequent hook calls — this is how you keep state.

registering a command

You can register commands that users invoke from the rxx command line. The command name uses / as a separator, and the corresponding handler function replaces / with _: 

fn init(session_in, renderer_in) {
    let session = session_in;
    let renderer = renderer_in;
    register_command(
        "greet/hello",
        "Say hello"
    );
}

fn cmd_greet_hello(args) {
    print(`Hello! Args: ${args}`);
}

The command :greet/hello is now available in the editor.

custom script modes

Scripts can define custom modes that integrate with the editor's mode system. When a script mode is active, your plugin receives mouse and cursor events: 

fn init(session_in, renderer_in) {
    let session = session_in;
    let renderer = renderer_in;
    let my_mode = script_mode("my tool");
    register_command("tool/start", "Start my tool");
}

fn cmd_tool_start(args) {
    session.switch_mode(my_mode);
}

fn mouse_input(state, button, cursor) {
    if session.mode != my_mode { return; }
    if state == INPUT_STATE_PRESSED
        && button == MOUSE_BUTTON_LEFT {
        print(`clicked at ${cursor}`);
    }
}

fn switch_mode() {
    // called when leaving the mode
    if session.prev_mode == my_mode {
        print("left my tool mode");
    }
}

plugin lifecycle

Every plugin can implement any subset of these hooks. All are optional except init, which is where you capture the session and renderer references.

hook signature when
init fn init(session, renderer) Once on plugin load. Store session and renderer in local variables.
draw fn draw() Every frame. Draw overlays (text, lines) on top of the editor.
shade fn shade(encoder) Every frame before render. Run GPU compute or render passes on off-screen textures.
render fn render(pass) Every frame. Draw into the main screen framebuffer using custom pipelines.
mouse_input fn mouse_input(state, button, cursor) Mouse button press or release.
mouse_wheel fn mouse_wheel(delta) Mouse wheel scroll.
cursor_moved fn cursor_moved(p) Mouse cursor moved.
switch_mode fn switch_mode() When the editor leaves a script mode. Check session.prev_mode.
view_added fn view_added(view_id) A new view (image tab) was opened.
view_removed fn view_removed(view_id) A view was closed.
cmd_* fn cmd_<name>(args) Called when a registered command is invoked. / in the command name becomes _.

A view represents an open image in the editor. Obtained via session.view(id) or session.views().

gpu rendering

rxx exposes a GPU rendering API built on wgpu. This is for advanced plugins that need to run custom shaders — for example, image filters, rotations, or procedural effects.

renderer.create_compute_texture(w, h, d) Create a 3D compute texture.

the shade hook

The shade(encoder) hook gives you a GPU command encoder. Use it to run off-screen render or compute passes: 

fn shade(encoder) {
    let tex = renderer.view_staging_texture(
        session.active_view_id
    );
    let pass = encoder.begin_render_pass(
        "my_effect",
        [color_attachment(tex, load_load(), store_store())]
    );
    pass.set_pipeline(pipeline);
    pass.set_bind_group(0, transform_bg);
    pass.set_bind_group(1, texture_bg);
    pass.set_vertex_buffer(0, vbuf);
    pass.draw(6, 1, 0, 0);
}

Color attachment helpers:

  • color_attachment(texture, load_op, store_op) — create a color attachment.
  • load_load() — preserve existing contents.
  • load_clear(r, g, b, a) — clear with a color.
  • store_store() — store the result.

the render hook

The render(pass) hook gives you a render pass targeting the screen. Use it to draw custom geometry into the final output: 

fn render(pass) {
    let vid = session.active_view_id;
    let view = session.view(vid);
    let bg = renderer.create_view_transform_bind_group(
        session.offset_x + view.offset.x,
        session.offset_y + view.offset.y,
        view.zoom.to_float()
    );
    let tex_bg = renderer.create_texture_sampler_bind_group(
        renderer.view_render_texture(vid)
    );
    pass.set_pipeline(my_pipeline);
    pass.set_bind_group(0, bg);
    pass.set_bind_group(1, tex_bg);
    pass.set_vertex_buffer(0, my_vbuf);
    pass.draw(6, 1, 0, 0);
}

examples

mode indicator overlay

A simple plugin that shows the current editor mode in the corner: 

fn init(session_in, renderer_in) {
    let session = session_in;
    let renderer = renderer_in;
}

fn draw() {
    let mode = session.mode.to_string();
    let color = if mode == "normal" {
        rgb8(255, 255, 255)
    } else if mode.starts_with("visual") {
        rgb8(0xff, 0x33, 0x66)
    } else {
        rgb8(0, 255, 0)
    };
    draw_text(vec2(10.0, 10.0), mode, color);
}

tracking views with commands

A plugin that tags views and draws labels above them: 

fn init(session_in, renderer_in) {
    let session = session_in;
    let renderer = renderer_in;
    let tagged = #{};
    register_command("tag/on", "Tag active view");
    register_command("tag/off", "Untag active view");
}

fn cmd_tag_on(args) {
    let vid = session.active_view_id;
    tagged[`${vid}`] = true;
}

fn cmd_tag_off(args) {
    let vid = session.active_view_id;
    tagged.remove(`${vid}`);
}

fn draw() {
    for view in session.views() {
        if `${view.id}` in tagged {
            let x = session.offset_x + view.offset.x;
            let y = session.offset_y + view.offset.y - 20.0;
            draw_text(vec2(x, y), "TAGGED", rgb8(0, 255, 0));
        }
    }
}

fn view_removed(view_id) {
    tagged.remove(`${view_id}`);
}
